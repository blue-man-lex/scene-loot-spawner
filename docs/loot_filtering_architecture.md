# Архитектура фильтрации генератора лута (Loot Spawner)

## 1. Общая концепция
Генератор лута (Loot Spawner) использует многоуровневую систему фильтрации для выборки предметов из компендиумов. Архитектура построена с учетом нестандартной структуры данных в пользовательских модулях (например, `blue-man-crafting`), где подтипы могут отсутствовать или не соответствовать стандартным (например, ингредиенты как `food`).

## 2. Уровни фильтрации
Процесс отбора кандидатов (`lootGenerator.js`) проходит через следующие этапы:

1. **Глобальный бан-лист (Blacklist):**
   - Блокируются предметы, содержащие в названии `(список)`.
   - Блокируются конкретные ID технических предметов или чертежей (например, `zf7yq3tTVk8LMEbI`, `BRn9yumP9nYdq8Fd`).

2. **Фильтрация по пользовательским папкам:**
   - Если пользователь выбрал конкретные папки в UI меню (Аккордеон), предмет отбрасывается, если его `folder` не совпадает со списком разрешенных.

3. **Базовый тип предмета (Type):**
   - Строгая проверка на совпадение `item.type` (например, `weapon`, `consumable`, `loot`, `equipment`).

4. **Проверка подтипа (Subtype) и магических свойств (Magic):**
   - *Подтип:* Проверяются поля `system.type.value` и `system.type.subtype`. Если профиль требует подтип (например, `gem`), а у предмета он отсутствует (`""`), предмет **отбрасывается**. Это гарантирует строгую целостность данных.
   - *Магия:* Если профиль требует `magic: true`, проверяется наличие свойства `system.properties.magical` у предмета.

5. **Ограничения редкости (Tier-based Rarity Cap):**
   - Отбрасываются предметы, чья редкость превышает максимальную допустимую для текущего Тира (Tier).
     - Tier 1 (CR 0-4): Максимум `uncommon`.
     - Tier 2 (CR 5-10): Максимум `rare`.
     - Tier 3 (CR 11-16): Максимум `veryRare`.
     - Tier 4 (CR 17+): Любая редкость (до `artifact`).

## 3. Логика профилей (config.js)
Профили описывают, какие именно фильтры применяются для конкретного типа сундука. Примеры строгих профилей:
- **Treasure (Сокровищница):** Требует `subtype: "gem"` для драгоценностей, либо `magic: true` для оружия/брони.
- **Lair (Логово):** Сфокусирован на крафте. Требует `subtype: "crafting"`, `subtype: "ingredient"`, а также допускает магическое оружие.
- **Library (Библиотека):** Требует `subtype: "scroll"`, `subtype: "ingredient"` (алхимия), `subtype: "material"` (пергамент).

*Примечание:* Из-за строгости фильтров, база данных компендиумов (предметов) должна содержать корректно заполненные поля `type` и `subtype`.

## 4. Ограничения количества (Stack Sizes)
Для предотвращения избыточного количества редких предметов в одном слоте лута введена жесткая балансировка:
- **Оружие и броня:** Всегда 1 шт.
- **Свитки и книги:** Всегда 1 шт.
- **Предметы редкости `rare` и выше:** Всегда 1 шт.
- **Остальной лут (расходники, сырье, обычные гемы):** Бросок от 1 до 3 шт. (`1d3`).

## 5. Важные замечания для разработчиков
- Любые новые профили генерации должны добавляться в `config.js` в раздел `profiles`.
- Ограничения на новые типы "единичных" предметов добавляются в секцию логики количества `LootGenerator.generateLoot()`.
- ИИ-ассистенты не должны ослаблять фильтры (например, убирать проверки `subtype`) ради совместимости с кривыми данными. Данные в модуле-источнике (`blue-man-crafting`) должны корректироваться вручную или через миграции.
