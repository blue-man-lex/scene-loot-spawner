# Выбор папок внутри компендиумов (Архитектура)

## Проблема
По умолчанию Foundry VTT позволяет обращаться только к целым компендиумам по их системному ID (например, `dnd5e.items`). Однако для больших модулей контента (таких как крафт или огромные библиотеки) пользователю может понадобиться подключить только определенные папки, чтобы не засорять генерацию лута ненужными предметами (например, заклинаниями, когда нужны только ресурсы).

## Решение

### 1. Формат хранения (Settings)
Настройка `lootSources` теперь является массивом строк (`Array`). 
- Если пользователь выбрал весь компендиум целиком, сохраняется стандартный ID пака: `"dnd5e.items"`.
- Если выбрана конкретная папка, сохраняется составной ID в формате `packId:folderId`, например: `"blue-man-crafting.BG3:d8F2kL9a"`.

### 2. Изменения в UI (LootSourcesMenu)
В файле `settingsMenu.js` при сборе данных (`getData()`) мы:
1. Запрашиваем все Item-компендиумы.
2. Для каждого компендиума проверяем его коллекцию папок (`pack.folders`).
3. Если папки есть, формируем древовидную структуру (компендиум выступает корнем, папки — ветвями).
4. Отрисовываем отступы в HTML-шаблоне.

### 3. Запрос данных (getIndex)
Ключевое изменение в парсерах лута (`lootGenerator.js` и `ingredientGenerator.js`).
1. При парсинге настроек мы группируем выбранные ID по `packId`.
2. Если для пака был указан маркер "все" (ID без двоеточия), пак грузится целиком.
3. Если указаны только `folderId`, мы:
   - В запрос `pack.getIndex({ fields: [...] })` обязательно добавляем поле `"folder"`.
   - После получения массива `index` фильтруем его, оставляя только те элементы, у которых `item.folder` совпадает с одним из разрешенных `folderId` для этого пака.

Это решение минимизирует количество изменений в кодовой базе и гарантирует 100% обратную совместимость с предыдущими сохранениями.
